SAÉ 1.05 – Traiter des données

1. Contexte et Objectifs de la mission

Contexte professionnel : Un professionnel R&T est régulièrement amené à manipuler des données brutes issues du système d'information (comme des logs, c'est-à-dire les journaux d'événements enregistrant l'activité des serveurs). Ces traitements, souvent récurrents et chronophages, gagnent à être automatisés via des scripts.

Mission confiée : L'objectif de ce projet de développement en Python était de récolter des données géographiques via une API REST en ligne (une Interface de Programmation permettant à des applications de s'échanger des données via le Web). Il fallait ensuite les traiter par parsing (analyse syntaxique du format JSON, un format de texte léger et hiérarchisé), en extraire les informations utiles, puis générer automatiquement un rapport visuel formaté en Markdown (langage de balisage léger) converti en HTML.

Compétences BUT ciblées : RT3 - Créer des outils et des applications informatiques pour les R&T.

2. Apprentissages Critiques (AC) mobilisés

Au cours de ce projet de programmation, j'ai particulièrement mis en œuvre les apprentissages suivants :

  • AC 13.02 : Lire, exécuter, corriger et modifier un programme.
    → Comment je l'ai mobilisé : En écrivant des fonctions Python complexes pour interroger des serveurs distants, en gérant les erreurs de connexion réseau et en manipulant dynamiquement des images.
  • AC 13.05 : Choisir les mécanismes de gestion de données adaptés au développement de l’outil.
    → Comment je l'ai mobilisé : En comprenant et en exploitant l'arborescence de données JSON retournée par l'API, un format beaucoup plus structuré et facile à manipuler informatiquement qu'un texte brut.

3. Tâches réalisées et Méthodologie

Pour mener à bien ce projet d'automatisation, j'ai adopté une démarche de développement modulaire en découpant mon script Python en plusieurs fonctions distinctes. Le processus s'est articulé autour de quatre grandes phases :

  • Phase 1 - Collecte des données : J'ai utilisé la bibliothèque requests pour lancer une requête GET (méthode standard pour demander une donnée à un serveur) vers l'API publique d'OpenStreetMap. J'ai intégré une gestion des erreurs (vérification du code HTTP 200) pour garantir que le script ne plante pas si le serveur distant est indisponible.
  • Phase 2 - Parsing et Extraction (Manipulation du JSON) : L'API renvoyant un flux brut d'informations, j'ai développé des routines pour naviguer dans l'arborescence du fichier JSON. En Python, cela se traduit par la manipulation de listes et de dictionnaires (des structures de données associant des clés à des valeurs). Mon code extrait ainsi les coordonnées GPS et les tags pertinents (nom, cuisine, horaires).
  • Phase 3 - Traitement Mathématique et Génération Visuelle : C'est la phase la plus technique (Trace 1). J'ai programmé des formules trigonométriques complexes pour convertir les coordonnées GPS (latitude/longitude) vers des coordonnées de "tuiles X/Y" (les petites images carrées qui composent une carte numérique). La bibliothèque d'images PIL (Pillow) télécharge ensuite la tuile, calcule la position en pixels, et dessine un repère rouge sur le bâtiment.
  • Phase 4 - Automatisation du Reporting : La dernière étape formatte ces données pour un utilisateur non-technique (Trace 2). J'ai utilisé la concaténation de variables en Python pour générer un fichier Markdown intégrant le texte et l'image de la carte, qui est ensuite automatiquement converti en page web HTML.

5. Autoévaluation et Démarche Réflexive

Difficultés rencontrées & Solutions apportées

J'ai rencontré deux grandes difficultés techniques lors de la phase d'analyse de données (parsing). Tout d'abord, lors de mes premiers tests, le serveur OpenStreetMap me bloquait l'accès avec une erreur HTTP 403 (Forbidden/Interdit). Après quelques recherches, j'ai compris que l'API rejetait les requêtes des programmes non identifiés. J'ai résolu ce problème en configurant un en-tête d'identification headers = {'User-Agent': 'Projet/1.0'} dans ma requête Python pour me déclarer proprement auprès du serveur, comme visible sur la Trace 1.

Ensuite, mon programme s'arrêtait brutalement avec une exception fatale de type KeyError (erreur survenant lorsqu'un programme cherche une clé inexistante). Cela arrivait car tous les bâtiments de la carte n'ont pas forcément les mêmes données renseignées. Pour rendre mon code plus "robuste" et éviter les crashs, j'ai modifié ma façon de lire le dictionnaire JSON : au lieu d'appeler directement la clé de manière rigide, j'ai utilisé la méthode d'interrogation sécurisée .get('phone', 'Non renseigné'). Ainsi, si l'information est absente, le script gère l'anomalie en affichant simplement une valeur par défaut.

Prise de recul (Bilan)

Cette SAÉ m'a fait faire un bond en avant dans ma compréhension de l'architecture logicielle du Web. Avant, je voyais le code comme un outil fonctionnant de manière isolée sur un ordinateur. Désormais, j'ai compris comment les API REST permettent à des systèmes hébergés dans le monde entier de se parler de manière universelle grâce au format JSON.

Capacité d'adaptation

Comprendre l'interrogation d'API et le traitement de données (JSON parsing) est une base absolue pour mon futur en cybersécurité. Par exemple, je pourrai réutiliser cette même logique en Python pour scripter des requêtes automatisées vers des moteurs de recherche de vulnérabilités (comme Shodan) lors d'une phase de collecte d'informations sur des cibles publiques (OSINT - Open Source Intelligence). Je pourrai également utiliser ces compétences pour interroger l'API d'un pare-feu Cisco (via le protocole RESTCONF) afin d'en extraire et d'en auditer automatiquement les règles de sécurité.
